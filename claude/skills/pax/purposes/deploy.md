## 目的：deploy（部署 / 上线 / 投产）

**适用**：把已构建、可识别版本的产物投放到目标运行环境并确认可服务。`ship` 负责代码发布闸、tag 与 push；`deploy` 负责运行环境变化。两者可串联，但不可混为一个目的。

部署会改变外部运行状态，属于高风险任务：必须先有回滚点，最终必须由未参与部署的独立 agent 验收。

---

### deploy 独有的必展开章节

#### 1. 部署目标与拓扑

明确环境、目标节点 / 集群、服务与版本、流量入口、依赖服务、部署窗口及影响面。必须给出“流量入口 → 网卡 / 负载均衡 → 服务进程 → 外部依赖”的 ASCII 拓扑，不在命名和说明中写死可变实例值。

#### 2. 配置契约

写实现或部署脚本前，逐项定义本次部署涉及的配置：

| 名称 | 类型 | 默认值 | 取值范围 / 约束 | 来源 | 为何是配置 |
|------|------|--------|-----------------|------|------------|
| `<key>` | `<type>` | `<value / 无>` | `<constraint>` | 环境变量 / 配置文件 / CLI | `<随部署或运维变化的原因>` |

只放部署差异：endpoint、凭据引用、超时、重试、并发、日志级别、路径、端口、资源配额。业务规则仍留在代码。报告只记录非敏感值；密钥只报告来源与是否就绪。

#### 3. 部署策略与回滚

从原子替换、滚动、蓝绿、金丝雀中选择并说明理由。明确：

- 健康检查、就绪条件、流量切换和扩容 / 缩容顺序
- 回滚触发阈值、操作、预计恢复时间及数据兼容性
- 数据迁移与应用版本的先后关系；不可逆迁移必须单独警示
- 部署前可恢复快照、旧版本或镜像 digest

#### 4. 运行态验收

至少覆盖：

- 版本 / 镜像 digest 与目标一致，进程和副本数正确
- readiness、liveness、关键业务探针通过
- 错误率、延迟、吞吐、CPU、内存、磁盘、网络无异常
- 关键日志无新增 ERROR；告警和 dashboard 可用
- 回滚路径已验证，或明确说明为何只能静态核查

每项给出命令、查询或观察入口及通过阈值。

#### 5. 部署上下文报告

最终验收报告必须记录**验收时实际观测值**：

| 类别 | 必报内容 |
|------|----------|
| 身份 | 环境、节点 / 集群、服务、版本、commit、镜像 digest、部署时间窗 |
| CPU | CPU 型号、物理 / 逻辑核；进程实际使用或亲和的 CPU / NUMA 节点 |
| 网卡 | 实际承载流量的接口、驱动、链路速率 / 状态、绑定地址或网络角色 |
| 内存与存储 | 总量 / 限额 / 使用量、挂载点、数据与临时目录 |
| 日志 | 应用日志、系统 / 服务管理器日志、部署工具日志的实际路径或查询入口 |
| 运行态 | PID / 容器 / Pod、副本分布、监听端口、健康检查结果 |
| 观测 | metrics、traces、dashboard、告警入口及验收窗口 |

云厂商或容器平台拿不到物理信息时，报告可见的 vCPU、实例类型、资源 limit / request、虚拟网卡和节点信息，并把不可见项标为 `BLOCKED`，不得猜测。地址、token、证书内容等敏感信息必须脱敏。

### deploy 实施计划的特殊约束

```
阶段 0: 前置检查与回滚点
  - 核对目标、权限、容量、依赖、配置和制品完整性
  - 捕获当前版本、运行指标、配置摘要和可恢复点
  - 验收：前置条件与回滚操作可执行

阶段 1: 投放但不切全量流量
  - 拉取并校验制品；应用配置；启动最小实例 / canary
  - 验收：版本正确，进程存活，readiness 通过

阶段 2: 切换与观测
  - 按策略逐步切流；持续观察业务与资源指标
  - 验收：达到计划流量，所有运行态阈值通过

阶段 3: 收尾与独立验收
  - 清理临时资源但保留回滚能力
  - 采集部署上下文，交独立 agent 对照原始验收条件检查
  - 交付物：带证据的验收报告
  - 验收：必需项全部 PASS；否则回滚或标记部署失败
```

任何阶段失败都先停止扩流，再按预定回滚点恢复；不得带病继续扩大影响面。

---

### deploy 的生产级重点

- **正确性**：制品身份、配置、数据 schema 与运行版本一致。
- **资源与性能**：容量和 limit / request 有依据；观察真实 CPU、内存、磁盘、网络。
- **可观测性**：部署动作、流量切换、探针、关键指标和失败分支均留痕。
- **安全**：最小权限；凭据不进命令历史、日志或报告；传输与制品校验有效。
- **可维护性**：部署步骤幂等；重复执行不会制造重复资源或破坏现状。

### 反模式

- ❌ 未定义回滚点就修改生产环境
- ❌ 用“进程启动成功”代替业务与运行态验收
- ❌ 报告只写计划配置，不采集实际 CPU、网卡、日志路径和运行资源
- ❌ 猜测平台不可见信息，或在报告中泄露敏感值
- ❌ 在同一次部署中夹带未经过 ship / test 的代码修改
- ❌ 验收失败仍宣称上线完成
